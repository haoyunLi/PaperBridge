## Recent input and layout changes, released in 0.2.18

These input and layout changes shipped in [Windows 0.2.18](https://github.com/haoyunLi/PaperBridge/releases/tag/windows-v0.2.18). Its exact source `5c6e71f` passed **203 unit tests, 33 desktop suites, and packaged startup** in [release CI](https://github.com/haoyunLi/PaperBridge/actions/runs/42346834301). Both public downloads were verified against their checksum files and GitHub asset digests; the installer completed an isolated 0.2.16→0.2.18 upgrade.

- **Inline text input:** Source contains a Paste Text disclosure, editable draft, Load Text and Clear. When a paper opens, the same draft remains inside Document & Import. Loading, cancellation, failure, disclosure changes and paper switches retain the draft; Clear affects only the draft, and successful saved-data removal clears it. Like the Mac view-model draft, it is not persisted across application restarts. During work the editor remains editable while Load Text and Clear are disabled; whitespace-only text cannot be loaded but can be cleared.
- **Opening behavior:** New pasted text with analysis paragraphs and a new practice paper open Overview. Text with no eligible analysis paragraphs opens Paper. Loading an existing checksum restores its saved tab, corrected source, annotations and other workspace data. The current change does not alter PDF import's initial tab. New-text completion reports analysis paragraphs and excluded reference blocks without changing their stored text or IDs; practice has its own fictional-document/no-model message.
- **Save and cancellation boundaries:** Import flushes the current paper before looking up the destination and again before replacing it. A same-paper reload prefers the latest in-memory snapshot. Flush drains both debounced notes and additional writes received while an older write is pending; a failed latest write remains retryable and prevents the switch. Cancellation is checked after asynchronous steps, and an older import cannot clear newer draft typing. The focused [save-queue tests](tests/paper-save-queue.test.cjs) passed **5/5**; the [paste desktop suite](tests/paste-text-e2e.cjs) passed its save/cancel boundaries, reset failure and retry, retained drafts and practice-paper checks without model requests.
- **Very short viewports:** At a CSS viewport height of 480px or less, [the Windows adaptation](src/compact-workspace.css) compacts the header and temporarily overlays Research Inspector instead of consuming the reading area's height. This extends the Mac-inspired sidebar/bottom-drawer layout; it is not a claim that Mac uses the same overlay. The [short-workspace desktop suite](tests/short-workspace-e2e.cjs) passed at a real 980×620 window with 200% zoom and at 1600×440, including note saves, scroll, close, undo, Focus Reading and normal drawer restoration. Full native screenshots were reviewed.

The public Portable executable was also checked with a real paper and its retained AMD translation, full-window screenshots, narrow sidebar controls and inline paste. Its short CSS viewport probe is recorded separately from the desktop suite's native 200% zoom checks. Evidence and unsigned-preview limitations are in the whole-app review.

Source evidence: [Mac paste controls](../PaperBridge/ContentView.swift#L214), [Mac text and practice loading](../PaperBridge/PaperReaderViewModel.swift#L787), [Mac saved-workspace restoration](../PaperBridge/PaperReaderViewModel.swift#L1545), [Windows source controls](src/SidebarSource.jsx), [Windows import flow](src/main.jsx), and [save queue](src/paperSaveQueue.mjs). These scoped changes do not establish complete feature or pixel parity.

## Functional changes in 0.2.19

These changes shipped in [Windows 0.2.19](https://github.com/haoyunLi/PaperBridge/releases/tag/windows-v0.2.19). Exact source `fad6717` passed 259 unit tests, 36 desktop suites and packaged startup in [release CI](https://github.com/haoyunLi/PaperBridge/actions/runs/42354219845). Both public binaries were downloaded and hash-verified. A real 0.2.18→0.2.19 upgrade and full installed/Portable restarts retained their respective old-paper and separately seeded selection/language/annotation fixtures. Public Portable also retained the original 15-page PDF and its existing AMD translation, with native and explicitly CSS-emulated short-viewport screenshots. This was preservation acceptance, with no new inference; stage 79 records the precise coverage and limits.

Selected paragraphs and Reader viewport positions now persist separately. Scrolling keeps the selected card and Inspector target; Current section follows the visible reading location. Search, paper switches, restarts and Back/Forward restore the two values independently. Reader text selection updates the paragraph choice, while Paper, PDF, Overview and Full Translation text selections retain their own scopes.

Structural edits select the edited result and map the existing Reader position. Undo restores the prior selection and viewport without reverting the current view mode, PDF zoom or later unrelated annotation/output changes. Old workspaces inherit their legacy viewport only when the selection field is missing; explicit null remains unselected on load. Focused unit and Electron coverage is recorded in whole-app review stage 76. These changes are included in 0.2.19 and are absent from the 0.2.18 executables.

Export headings and filenames now follow each saved artifact's own language. Reader paragraphs and connected batches retain language metadata through settings/source variants, partial resume and source repairs. Missing or contradictory historical metadata remains unknown; it does not borrow the current global language. A contradictory full draft stays unknown while resuming its old successful batches; full regeneration establishes a new direction. Summary headings use the summary's existing source/target fields independently.

Known bundle files use `paper_original.md`, `paper_translation_<target>.md`, `paper_bilingual_<source>_<target>.md`, `paper_analysis_notes.md` and `paper_full_translation_<target>.md`, with Mac language codes including `zh-Hans` / `zh-Hant`. Unknown languages omit the suffix. Default Analysis uses `<stem>_bilingual.md`; bundle folders use `<stem>_PaperBridge` with duplicates starting at `-2`. Windows keeps its additional single-file exports, hashed portable resource paths and PDF.js rendering with import-time page archives and export-time repair. Stage 77 records validation; these export changes are included in 0.2.19.

Saved annotations use a read-only projection to merge exact-anchor notes and highlights, preserving every original record and historical body. Clear surface/side labels, creation-time descending order and two-line full-text previews follow the Mac behavior. Unknown ranges remain separate; undated groups keep stable order without invented timestamps. Separate note/highlight removal retains its existing meaning, while Delete annotation removes the combined records in one Undo. Deleting the active note synchronizes the draft immediately; other pending note text remains intact. New counterpart records inherit the original annotation age, including unknown legacy dates, so removing one part keeps new groups in place. Historical record dates are not rewritten. Deletion and structural Undo preserve duplicate-ID bodies and multiplicity; ambiguous later changes are retained for review. The storage arrays, export ordering and exact navigation guards remain unchanged. Stage 78 records validation; these changes are included in 0.2.19.

## Functional changes in 0.2.20

[Windows 0.2.20](https://github.com/haoyunLi/PaperBridge/releases/tag/windows-v0.2.20) includes complete-token and grapheme-safe long-paragraph splitting and an independent library metadata index. Readable legacy papers migrate automatically. If both paper copies are unreadable, their indexed entry remains available for label/tag editing, with a clear unavailable state; opening it leaves the current paper intact. Label saves change only the index, and later paper autosaves cannot restore an older label. Reimporting the same source restores its original text under the same entry with the retained label. This does not recreate translations or annotations lost from both copies.

Release source `8315c8b` passed 273 unit tests, 36 desktop suites and packaged startup. Exact public files passed checksum/digest verification, real 0.2.19→0.2.20 upgrade, full installed/Portable restart and saved real-paper preservation. Separate public Portable workflows verified two requests bounded to 500 graphemes, formula/link restoration, independent label writes, actual dual-copy corruption and same-ID Paste Text recovery. Controlled model responses prove app-side integrity; real-model evidence is recorded separately in the AMD report. Whole-app review stage 82 records the evidence and limits.

## PDF recovery after 0.2.20

Development changes after 0.2.20 also align Re-extract PDF as New Copy with the Mac file chooser and selected-original naming. Ordinary same-original import verifies and atomically repairs the PDF asset without replacing the workspace or independent labels. A repeated open flushes notes before refreshing the workspace. Eight focused units and actual IPC/desktop import workflows cover cancellation, corrupted or mismatched assets, failed atomic replacement and an intentionally delayed latest note save; system-dialog results are injected by the test. Stage 84 records the evidence. These changes are not yet in the public 0.2.20 executables.

## GPU behavior

The Windows port detects video adapters, NVIDIA CUDA driver capability and Ollama's running-model VRAM use. On x64, managed MinerU 4.1.7 uses ONNX with DirectML or CPU. Eligible NVIDIA fresh installations retain the managed 3.4.5 CUDA path, with a runtime check and legacy pipeline fallback. RX 7800 XT logs confirm DirectML layout and text recognition, CPU detection, and full VRAM placement of the Ollama 4B model through ROCm. [AMD device report](AMD_DEVICE_TEST.md)
